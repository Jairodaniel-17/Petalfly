# **Petalfly**

Petalfly is a **100% local-first API client**. All requests, environments, and settings live as plain files inside the workspace — fully Git-friendly and version-controlled. The app combines React + Tauri + Rust to deliver a private desktop shell with **zero telemetry** and no cloud dependencies.

![Secret Manager](docs/screenshot-secrets.png)

## **Features**

* 🗂️ Full collection tree based on `/workspace/collections`
* ✍️ Postman-style tabbed editor for Params, Headers, Body, Auth, Tests, Docs, and raw `.pfs`
* 📚 Bidirectional Petalfly Script 1.0 parser (YAML-like + `"""` blocks)
* 🔐 Secret Manager with ChaCha20-Poly1305 + PBKDF2 encryption and in-memory master password
* ⚙️ Advanced Settings: theme, timeout, SSL, history, debug logs
* 📜 Per-request history (`workspace/history/<requestId>.json`) with payload restore
* 🧪 Visual test runner with JSONPath, status, header, and body assertions
* 📤 Perfectly equivalent cURL exporter + cURL → `.pfs` importer
* 🧵 Response panel with tabs: pretty/raw body, headers, tests, curl, history
* 🪶 UI inspired by floating petals (soft gradients + JetBrains Mono typography)

---

## **Tech Stack**

* **Frontend:** React 19 + Vite + Zustand + React Markdown
* **Backend:** Tauri 2 + Rust (`reqwest`, `serde_yaml`, `chacha20poly1305`)
* **Language:** Petalfly Script (`petalfly 1.0`) with custom parser and test suite

## **Requirements**

* Node.js 20+ and pnpm 9+
* Rust stable + required Tauri toolchains (MSVC on Windows, Xcode CLI on macOS)
* A workspace folder on disk (default `./workspace`)

## **Getting Started**

```bash
pnpm install
pnpm tauri dev
```

The initial workspace includes:

* `collections/sample.pfs` – demo request
* `environments/env.dev.yaml` – environment with a sample secret (`token`)
* `globals.yaml` – global variables
* `settings.json` – general configuration

## **`.pfs` Language**

```yaml
petalfly 1.0
meta:
  id: get-user
  name: Get User
  collection: Demo
  tags: [users]
  description: Retrieves a user
request:
  method: GET
  url: "{{baseUrl}}/users/{{userId}}"
  headers:
    Accept: application/json
  query:
    pretty:
      value: true
      enabled: true
  body:
    type: none
docs: """
## Documentation
Markdown is rendered live.
"""
tests:
  - name: status 200
    expect:
      status: 200
examples:
  - name: curl
    curl: |
      curl -X GET "{{baseUrl}}/users/{{userId}}"
```

* Variables: `{{name}}` → resolved using environments (`environments/*.yaml`) + `globals.yaml`
* `docs` uses `"""` blocks; any `|` block is preserved as multiline text
* Tests support `status`, `header.contains/equals`, `body.contains`, `json.path/type/equals`

## **Secrets & Environments**

1. Go to **Secret Manager** and set your master password (only lives in memory).
2. Create secrets (`secret: true`) inside the active environment.
3. Use **Reveal** to view them temporarily; **Encrypt & Save** persists them encrypted.
4. During execution, secrets are decrypted *only in memory* and never written to logs.

Environments are stored as YAML/JSON in `workspace/environments`. All secrets are saved encrypted; decrypted values stay cached only while the app is running.

## **Collection Tree**

The sidebar mirrors exactly the folder structure in `workspace/collections` (subfolders + `.pfs` files). From the menu you can:

* Create folders/requests
* Duplicate, rename, or delete files
* Import a cURL command and convert it automatically to `.pfs`

---

## **Response & History**

* **Body:** pretty JSON fallback → raw text
* **Headers:** key/value table
* **Tests:** runner results + “Run Tests Again” (without redoing HTTP)
* **Curl:** equivalent request curl command (copy to clipboard)
* **History:** last `N` results (configurable) with timestamp, status, and “Restore”

Each request stores its history at `workspace/history/<requestId>.json`.

---

## **Import / Export cURL**

* **Export:** open the *Curl* tab in the response panel → `Copy`.
* **Import:** click *Import cURL* in the sidebar → paste a command → creates `.pfs` with metadata and inferred headers/body.
